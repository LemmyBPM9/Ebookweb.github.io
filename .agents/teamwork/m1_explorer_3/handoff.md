## 2. Logic Chain

### 2.1 JSZip Vendoring Strategy (Zero Build Step)
1. *From* the user requirement of pure HTML/CSS/JS execution without build steps:
   - Modern bundlers (Vite/Webpack) require Node runtime compilation.
   - Standard browser `<script src="vendor/jszip.min.js"></script>` executed before ES modules places `window.JSZip` into the global execution context.
2. *From* ES module isolation:
   - Native ES modules (`<script type="module" src="js/app.js"></script>`) have access to global `window` properties.
   - Modules can directly access `window.JSZip` or use a defensive accessor `getJSZip()`:
     ```javascript
     function getJSZip() {
       const jszip = typeof window !== 'undefined' ? window.JSZip : globalThis.JSZip;
       if (!jszip) {
         throw new Error("JSZip library not found. Verify vendor/jszip.min.js is included in index.html.");
       }
       return jszip;
     }
     ```
3. *From* repository layout and licensing:
   - JSZip v3.10.1 is MIT licensed.
   - Vendoring directly into `vendor/jszip.min.js` satisfies zero-network, offline-first reliability.

### 2.2 Programmatic Sample EPUB Architecture (`js/sample-book.js`)
1. *From* EPUB Open Container Format (OCF 3.3) requirements:
   - The root archive must contain `mimetype` as its very first entry.
   - It must be uncompressed (`STORE` mode), have no extra fields, and contain exact ASCII bytes `application/epub+zip`.
   - By calling `zip.file("mimetype", "application/epub+zip", { compression: "STORE" })` first, JSZip marks the file record with compression method 0, even when `zip.generateAsync()` specifies default compression `DEFLATE`.
2. *From* dual EPUB 2 and EPUB 3 compatibility requirements:
   - Older readers and test cases rely on EPUB 2 NCX (`OEBPS/toc.ncx` declared via `<spine toc="ncx">`).
   - Modern readers require the EPUB 3 Navigation Document (`OEBPS/nav.xhtml` declared via `<item properties="nav">`).
   - Including both in `OEBPS/content.opf` ensures the sample EPUB validates against both parser code paths and exercises all navigation features.
3. *From* testing coverage requirements:
   - To verify the reading engine and UI capabilities in Milestone 3 and Milestone 4, the sample book must include:
     * **Drop Caps**: Tests floating layout, line-height normalization, and column breaking in Paginated View.
     * **Blockquotes & Citations**: Tests indentation, typography cascade, and border contrast.
     * **Inline SVG Diagram**: Tests vector scaling in multi-column layout, image height constraints (`max-height: calc(100vh - 120px)`), and theme inheritance via `currentColor`.
     * **Comparative Font Table**: Tests table overflow handling, responsive widths, and font family demonstrations.
     * **Internal Section Anchors**: All chapters include distinct section IDs (`#optical-mechanism`, `#scourge-of-glare`, `#four-palettes`, `#spectrum-diagram`, `#measure-and-leading`, `#typeface-table`) mapped 1-to-1 in both `toc.ncx` and `nav.xhtml`, enabling precise bookmark and TOC jumping tests.
4. *From* auto-seeding and storage integration requirements:
   - When the library is initialized, `StorageManager.getAllBooks()` is queried.
   - If empty (or sample book is missing), `seedSampleBookIfEmpty(storageManager)` generates the EPUB Blob, constructs a complete `BookRecord` with deterministic ID `sample-book-001`, saves it to IndexedDB, and returns the record.
   - An explicit `restoreSampleBook(storageManager)` function is provided for user-triggered restoration from the library UI.

## 4. Caveats
1. **Per-File Compression Flag Override**:
   In JSZip, the root option `{ compression: 'DEFLATE' }` in `generateAsync` applies to every entry *unless* an entry explicitly specifies `{ compression: 'STORE' }` during `zip.file()`. The implementer **must** include `{ compression: 'STORE' }` when adding `'mimetype'`. Omitting this parameter will cause JSZip to deflate `mimetype`, which violates EPUB 3 OCF Section 3.3.
2. **File Insertion Order**:
   JSZip maintains dictionary insertion order for directory headers. `zip.file('mimetype', ...)` must be the very first call before any other files or folders are added to ensure it occupies the first local header block at offset 0.
3. **Blob URL Creation for SVG Cover**:
   The sample book declares `<item id="cover-image" href="images/cover.svg" media-type="image/svg+xml" properties="cover-image"/>`. In Milestone 2 (Parser), the asset extractor must create a Blob URL with type `image/svg+xml`. If converted to an image element or object URL, modern browsers render SVG covers crisply without raster pixelation.
4. **Offline Zero-Network Guarantee**:
   Because `vendor/jszip.min.js` is vendored locally and `js/sample-book.js` generates all XML, CSS, SVG, and text in memory, the user experience is 100% functional offline without requesting external CDNs.
